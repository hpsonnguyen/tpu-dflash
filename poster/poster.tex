\posterblock{Problem \& Motivation}

\posteritem
\begin{itemize}\setlength\itemsep{4pt}
  \item LLM decoding is \textbf{inherently sequential}: generating $n$ tokens
        requires $n$ forward passes through the full target model, making
        latency grow linearly with output length.
  \item \textbf{Speculative decoding} uses a lightweight \emph{draft model}
        to propose $K$ candidates; the target verifies all in one batched
        forward pass. Higher-quality drafts yield more accepted tokens per step.
  \item \textbf{Our contribution:} Port DFlash---a diffusion-based block
        drafter---from GPU/PyTorch to TPU/JAX inside \texttt{tpu-inference}.
        Benchmark Qwen3-4B across 9 datasets (math, code, chat).
  \item \textbf{Why TPU?} Verification cost is \textbf{flat from $K$=16 to
        $K$=128} (0.97$\times$), while GPU scales to 2.3$\times$---ideal for
        aggressive speculative decoding with wide draft blocks.
\end{itemize}

\posterblock{Background}

\posteritem
{\postersubsection\bfseries\color{navy} Speculative Decoding\par}\vspace{1pt}
\begin{itemize}\setlength\itemsep{3pt}
  \item A fast draft model generates $K$ candidates; the target scores all
        $K$ in one pass via rejection sampling.  Accepted tokens are emitted
        \emph{without recomputation}.
  \item Key metric: $\tau$ = average accepted tokens per draft step.
        Ideal $\tau \to K$; limited by draft--target distribution mismatch.
\end{itemize}

\vspace{3pt}
{\postersubsection\bfseries\color{navy} Draft Model Approaches\par}\vspace{1pt}
\begin{itemize}\setlength\itemsep{3pt}
  \item \textbf{N-gram:} Near-zero latency but low $\tau$ (poor approximation).
  \item \textbf{Eagle3:} Autoregressive drafter; high $\tau$ but $O(K)$
        sequential passes---draft latency grows with block size.
  \item \textbf{DFlash:} Diffusion-based block drafter---all $K$=16 tokens in
        \textbf{one pass} via non-causal attention. Draft cost is $O(1)$
        regardless of $K$, uniquely suited for TPU's flat verification profile.
\end{itemize}

\vspace{3pt}
{\postersubsection\bfseries\color{navy} DFlash Architecture\par}\vspace{1pt}
\begin{itemize}\setlength\itemsep{3pt}
  \item 4-layer transformer with non-causal block attention; each draft token
        attends bidirectionally to all other draft tokens.
  \item Reuses target model's embedding layer and LM head (no extra params).
  \item Conditioned on target hidden states from layers [1,\,9,\,17,\,25,\,33],
        projected via FC + RMSNorm.
  \item Trained on only 289K samples; outperforms Eagle3 (1.4M samples).
\end{itemize}

\posterblock{Methods: GPU $\rightarrow$ TPU}

\posteritem
\begin{enumerate}\setlength\itemsep{4pt}
  \item \textbf{Dual KV cache:} Paged KV (PagedAttention) for target; static
        JAX KV with \texttt{dynamic\_update\_slice} for draft.
  \item \textbf{Non-causal attention:} TPU \texttt{flash\_attention} with
        \texttt{causal=False} for bidirectional draft-token attention.
  \item \textbf{Critical bug fix---sequence-length inflation:}
        Phantom tokens ($\sim$15/step) corrupted RoPE embeddings. Fixing this
        \emph{nearly doubled performance:}\\[1pt]
        \hspace*{1em}$\tau$: 2.49 $\to$ 4.48 \quad
        Speedup: 1.30$\times$ $\to$ 2.31$\times$
  \item \textbf{Hidden-state extraction:} Layers [1,9,17,25,33] concatenated
        and projected via learned FC + RMSNorm.
  \item \textbf{Method registration:} New \texttt{"dflash"} branch in
        \texttt{tpu\_runner.py} with prewarm and cache-reset support.
\end{enumerate}
\vspace{1pt}
Zero new vLLM dependencies. Full DFlash contract preserved.

\resultbox{%
\posteritem
\begin{itemize}\setlength\itemsep{3pt}
  \item \textbf{Setup:} Qwen3-4B + DFlash block-16 on TPU V5P (4 chips),
        evaluated on \textbf{9 benchmarks} in 3 categories.
  \item \textbf{Math} (gsm8k, math500, aime24, aime25): \textbf{3.72$\times$}
        avg.\ speedup, $\tau$=6.71. \emph{Math500 peaks at 4.93$\times$}
        ($\tau$=8.80), exceeding GPU paper's $\tau$=7.84.
  \item \textbf{Code} (humaneval, mbpp): \textbf{2.77$\times$} avg.\ speedup,
        $\tau$=5.09. Structured patterns boost acceptance.
  \item \textbf{Chat} (mt-bench, alpaca, swe-bench): \textbf{1.96$\times$}
        avg.\ speedup, $\tau$=3.37. Higher entropy limits draft accuracy.
  \item \textbf{Output quality preserved:} Divergence is numerical (bf16
        rounding), not semantic errors.
\end{itemize}
}

\posterblock{TPU vs GPU Draft Quality}

\begin{center}
  \includegraphics[width=0.95\linewidth]{figures/tpu_vs_gpu_parity.pdf}
\end{center}

\vspace{2pt}
\posteritem
\begin{itemize}\setlength\itemsep{3pt}
  \item \textbf{Draft quality parity:} Our TPU port achieves \textbf{94.9\%}
        of GPU A100 $\tau$ across the 4 math benchmarks with available GPU data.
  \item Math500 \emph{exceeds} GPU at \textbf{112\%}---the only benchmark
        where TPU surpasses the original GPU implementation.
  \item Remaining $\sim$5\% gap attributed to bf16 precision and minor
        attention kernel divergence between PyTorch and JAX.
\end{itemize}

\posterblock{Acceptance Rate by Position}

\begin{center}
  \includegraphics[width=\linewidth]{figures/acceptance_decay.pdf}
\end{center}

\vspace{1pt}
\posteritem
\begin{itemize}\setlength\itemsep{3pt}
  \item Math benchmarks maintain $>$70\% acceptance through positions 8--10,
        reflecting high predictability of step-by-step reasoning.
  \item Chat tasks drop below 50\% by position 4--5 due to higher output
        entropy and creative language patterns.
  \item DFlash's \textbf{non-causal attention} lets each position attend
        bidirectionally, sustaining quality at later draft positions.
  \item Even at position 16, math retains $>$20\% acceptance, justifying
        wide $K$=16 blocks.
\end{itemize}

\begin{itemize}\setlength\itemsep{3pt}
  \item TPU V5P: \textbf{\$1.36/M tokens} avg.\ vs.\ \$2.08 (V4) and
        \$2.94 (GPU A100 est.)---the most cost-efficient option.
  \item Verification (46.9\%) and acceptance (14.5\%) dominate step time;
        draft forward is only 2.7\% ($\sim$54\,ms).
  \item \textbf{Pipeline overhead} (host--device transfer, cache mgmt.)
        explains the standalone--pipeline $\tau$ gap (5.42 vs 4.48).
\end{itemize}

\posterblock{Conclusion \& Future Work}

\posteritem
\begin{itemize}\setlength\itemsep{3pt}
  \item DFlash on TPU V5P: \textbf{3.01$\times$ standalone},
        \textbf{2.31$\times$ pipeline} speedup with no quality loss.
  \item TPU's flat verification scaling makes it the ideal hardware for
        speculative decoding with large draft blocks.
  \item Most cost-efficient inference configuration among all
        hardware--method combinations tested.
\end{itemize}

\vspace{2pt}
{\postersubsection\bfseries\color{navy} Future Work\par}\vspace{1pt}
\posteritem
\begin{itemize}\setlength\itemsep{3pt}
  \item \textbf{Wider blocks ($K$=64, 128):} Both draft and verify stay flat
        on TPU---should scale near-linearly.
  \item \textbf{vLLM optimization:} Reduce host--device overhead to close the
        standalone--pipeline gap.
  \item \textbf{LM head fusion:} Two matmuls account for $\sim$30\% of step
        time and can be fused into one kernel.
\end{itemize}
