Toward Accelerated LLM Inference: Porting and Evaluating Diffusion-Based Speculative Decoding on TPU

Autoregressive decoding is inherently sequential: generating n tokens requires n target-model forward passes. We port DFlash, a diffusion-based speculative decoding method that drafts a whole token block in parallel, to TPU in JAX within the vLLM TPU inference stack, and benchmark both standalone loops and serving-pipeline integration.

Problem and Motivation

In standard decoding, large language models generate one token at a time; each new token depends on all prior tokens. This sequential dependency makes long-form generations, especially chain-of-thought style reasoning, slow and expensive, because the target model must run once per output token.

Our work ports DFlash from GPU/PyTorch to TPU/JAX inside tpu-inference, evaluates performance in both standalone and vLLM pipeline settings, compares against autoregressive drafting (Eagle3), and checks that output quality is preserved.

Background

Speculative decoding reduces the cost of autoregressive generation by splitting decoding into two stages: a lightweight draft model proposes a short continuation, and the full target model verifies those candidates in a single batched pass. The key metric is the average acceptance length τ: how many draft tokens are accepted per verification step.

DFlash replaces sequential (autoregressive) drafting with a diffusion-style block drafter that predicts an entire fixed-size token block in one forward pass using non-causal attention. That parallel, dense computation pattern aligns well with TPU hardware, making it a natural candidate for porting.

Methods: GPU → TPU Migration

Key engineering steps

  • Dual KV cache architecture: keep paged KV for the target (vLLM PagedAttention) while maintaining a separate static JAX KV cache for the draft’s non-causal block attention.
  • TPU attention kernel swap: use TPU flash attention with causal=false to match DFlash’s block-diffusion drafting pattern.
  • State alignment in verification: fix sequence-length bookkeeping so the proposer advances by the accepted token count, preventing drift across speculative iterations.

We preserve the DFlash interface: extract target hidden-state features, run a lightweight block drafter, reuse the target vocabulary/LM head for logits, then verify a full draft block in one target forward pass.

Standalone TPU vs GPU DFlash

Standalone loop throughput comparison between TPU (this port) and GPU (paper) DFlash numbers.

Standalone loop vs pipeline: Standalone measurements isolate the algorithm (prefill → draft → verify → accept) without vLLM scheduling, batching, or serving overhead.

Port parity: Acceptance behavior tracks closely across hardware; remaining TPS gaps are typically attributable to platform-level characteristics rather than a change in decoding behavior.

Acceptance Volume (τ × drafts/sec)

Accepted throughput decomposed as bar area = τ × drafts/sec. Height = τ; width = drafts/sec.

Meaning: τ is the mean number of accepted tokens per speculative step; drafts/sec captures how many draft blocks the system can propose and verify per second. Their product equals accepted tokens/sec.

DFlash vs Eagle3: DFlash is designed to push τ higher by drafting a full block in parallel, while autoregressive drafters trade off smaller draft steps against additional sequential work.

Conclusion

We demonstrate that diffusion-based speculative decoding transfers effectively to TPU: the DFlash port maintains strong acceptance behavior, delivers meaningful acceleration in both standalone and serving-pipeline settings, and preserves output quality relative to baseline decoding.

Beyond reproducing results on a new hardware stack, this implementation provides a clean foundation for upstreaming into tpu-inference and for future work on faster kernels, concurrent serving benchmarks, and broader diffusion-based speculative decoding research on TPU.
